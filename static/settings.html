Konto

Dein Zugang zum Dashboard. Beim Ändern des Passworts werden deine anderen Geräte abgemeldet.

Ansehen ohne Login

Für ein Wanddisplay: Jeder im Netzwerk sieht das Dashboard. Aktionen, Updates und diese Seite brauchen weiterhin ein Login.

Alle anderen Geräte abmelden

Beendet deine Sitzungen auf allen anderen Geräten – z.B. wenn ein Gerät verloren ging.

Zwei-Faktor-Anmeldung

Zusätzlich zum Passwort ein 6-stelliger Code aus einer Authenticator-App auf dem Handy. Wer dein Passwort kennt, kommt ohne das Handy nicht hinein. Für den Notfall gibt es einmalige Wiederherstellungscodes.

Passkeys

Anmelden mit Face ID, Touch ID, Windows Hello, dem Handy oder einem Sicherheitsschlüssel – ohne Passwort und Code, und sicher gegen gefälschte Anmeldeseiten. Ein Passkey zählt als Zwei-Faktor-Anmeldung. Funktioniert nur über HTTPS und unter der Adresse, unter der er angelegt wurde.

Sitzungen

Wo du gerade angemeldet bist – Gerät, Adresse und letzte Nutzung. Unbekannte Sitzungen hier beenden und danach das Passwort ändern.

Benutzer

Wer sich am Dashboard anmelden darf und in welcher Gruppe. Die Gruppe bestimmt die Rechte (siehe Berechtigungen). Deaktivierte Benutzer werden sofort abgemeldet.

Benutzer hinzufügen

Das Passwort teilst du der Person selbst mit – sie kann es danach unter „Konto“ ändern. Gastzugänge enden automatisch am Ende des Ablauftags (bei „1 Tag“ nach 24 Stunden); danach ist keine Anmeldung mehr möglich und laufende Sitzungen enden. Gäste können keine Administratoren sein.

Berechtigungen

Was jede Gruppe darf. Ein Haken wird sofort gespeichert und gilt ohne neue Anmeldung. Administratoren dürfen immer alles.

      Anmeldung per SSO

      –

      Anmeldung über einen OpenID-Connect-Anbieter wie Pocket ID, Authentik oder Keycloak. Beim ersten Mal wird das Konto beim Anbieter mit einem Dashboard-Benutzer verknüpft – über eine Gruppen-Zuordnung, den gleichen Benutzernamen oder die gleiche E-Mail-Adresse. Gruppen des Anbieters können die Dashboard-Gruppe bestimmen. Lokale Konten bleiben als Notzugang erhalten; ./set-password.sh auf dem Pi funktioniert immer.

      Konten zuordnen

      Gruppen-Zuordnung

      Gruppe beim Anbieter → Dashboard-Gruppe. Die erste passende Zeile gilt – privilegierte Gruppen nach oben.

      Verknüpfte Konten

      So wird es eingerichtet
      1. Beim Anbieter einen OIDC-Client (vertraulich, mit Secret) anlegen. Als Callback-URL die oben angezeigte Adresse eintragen – für jede Adresse, unter der das Dashboard geöffnet wird (z.B. Cloudflare-Domain und Heimnetz-IP), eine eigene.
      2. Bei Pocket ID: unter dem Client die erlaubten Benutzergruppen setzen und „PKCE“ aktivieren. Gruppen kommen mit dem Scope groups.
      3. Client-ID und Secret hier eintragen, „Anbieter testen“, dann einschalten und speichern.
      4. Erst nachdem die SSO-Anmeldung funktioniert, die lokale Anmeldung auf „Nur Administratoren“ stellen. Administratoren behalten Passwort und Passkey als Notzugang.
      5. „Bestätigen“ vor kritischen Änderungen geht dann auch über den Anbieter (öffnet ein kleines Fenster).

        Terminal-Mitschnitte

        Jede Web-Terminal-Sitzung wird aufgezeichnet und lässt sich hier wie ein Video abspielen – wer wann was auf dem Pi oder in welchem Container gemacht hat. Aufgezeichnet wird auch, solange kein Browser verbunden ist. Passwörter an einer sudo-Abfrage zeigt das Terminal nicht an, sie sind daher nicht enthalten. Nur Administratoren sehen die Mitschnitte; jedes Abspielen steht im Aktivitätsprotokoll.

        tmux ist nicht installiert – ohne dauerhafte Sitzungen gibt es keine Mitschnitte.

        Remote-Pis

        Weitere Raspberry Pis mit diesem Dashboard steuern. Auf dem anderen Pi läuft dazu der PiCore-Agent – dann lässt sich oben rechts zwischen den Pis wechseln, und alles (Live-Werte, Dienste, Container, Dateien, Terminal, Firewall, Updates …) zeigt den gewählten Pi. Rechte und Anmeldung bleiben die von diesem Dashboard.

        Pi hinzufügen

        So wird ein Pi zum Agent
        1. Auf dem anderen Pi das Repository klonen (wie beim ersten Pi) und im Ordner ./install.sh --agent ausführen.
        2. Am Ende stehen Adresse und Token im Terminal – beides hier eintragen. Später zeigt ./agent.sh token den Token wieder.
        3. Der Agent hat keine eigene Oberfläche und kein Login, aktualisiert sich aber wie dieses Dashboard automatisch von GitHub.
        4. Der Token wird im Klartext übertragen: Remote-Pis am besten nur im Heimnetz oder über das VPN (NetBird) ansprechen. Neuer Token: ./agent.sh rotate.

        NetBox

        Verbindet das Dashboard mit deiner NetBox. Unter System-Werkzeuge → NetBox erscheinen dann Präfixe, IP-Adressen, Geräte und VMs, abgeglichen mit dem Geräte-Scan dieses Pi.

        Welcher Token?
        1. In NetBox oben rechts Profil → API-Tokens → Token hinzufügen. NetBox 4.5+ zeigt den Token einmalig als nbt_…, ältere Versionen als 40 Zeichen langen Schlüssel – beides funktioniert.
        2. Zum Ansehen reicht ein Token ohne Schreibrechte. Wer Geräte aus dem Abgleich direkt in NetBox eintragen will, braucht Schreibrechte für IP-Adressen – und im Dashboard die Berechtigung „NetBox bearbeiten“.
        3. Der Token bleibt auf dem Pi und wird nie an den Browser zurückgegeben. Ohne neuen Token bleibt der gespeicherte erhalten, aber nur für dieselbe Adresse.
        4. Die Abfrage läuft vom Pi aus: NetBox muss vom Pi erreichbar sein (Heimnetz oder VPN).

        MCP-Server

        –

        Claude (claude.ai, Claude Desktop, Claude Code) kann das Dashboard über MCP bedienen: Überblick, Logs, Container, Updates, Doku, Aufgaben, Dateien … Die Anmeldung läuft per OAuth über Pocket ID; jede Pocket-ID-Identität wird einem Dashboard-Benutzer zugeordnet und hat genau dessen Rechte. Jede Aktion steht mit „(MCP)“ im Aktivitätsprotokoll.

        Zuordnung Pocket ID → Dashboard-Benutzer

        E-Mail-Adresse, Benutzername oder Subject aus Pocket ID. Nicht zugeordnete Identitäten werden abgewiesen.

        So wird es eingerichtet
        1. In Pocket ID einen OIDC-Client anlegen. Als Callback-URL die oben angezeigte Adresse eintragen (endet auf /auth/callback). Client-ID und Secret hier eintragen.
        2. Eine eigene Domain per Cloudflare Tunnel (oder Reverse Proxy) auf http://<Pi-IP>:8000 zeigen lassen. Unter dieser Domain liefert das Dashboard nur den MCP und die Anmeldung aus – die Oberfläche selbst bleibt im Heimnetz.
        3. In Claude unter Einstellungen → Connectors einen eigenen Connector mit der MCP-Adresse anlegen; bei der ersten Verwendung meldest du dich bei Pocket ID an.
        4. Claude Code: claude mcp add --transport http picore https://…/mcp

        MCP-Aktivität

        Aktionen, die Claude über den MCP ausführen möchte und die eine Freigabe brauchen, sowie das Protokoll aller Werkzeug-Aufrufe. Freigeben darf der zugeordnete Benutzer selbst oder ein Administrator – nie Claude.

        Werkzeug-Aufrufe

        Webhooks

        Eigene Adressen, an die andere Dienste Meldungen schicken – Uptime Kuma, Watchtower/Shoutrrr, GitHub oder eigene Skripte. Jede Meldung erscheint in den Ereignissen und im Wochenbericht; die Stufe (OK, Hinweis, Warnung, Kritisch) wird aus der Meldung erkannt oder fest vorgegeben. Höchstens 60 Meldungen pro Minute und Webhook.

        Beispiele
        1. Skript: curl -d "Backup fertig" http://<Pi>:8000/hook/<Token> oder JSON mit {"title": "…", "message": "…", "level": "error"}
        2. Uptime Kuma: Benachrichtigung „Webhook“, Body „Preset – application/json“, URL des Webhooks.
        3. Watchtower: WATCHTOWER_NOTIFICATION_URL=generic+http://<Pi>:8000/hook/<Token>
        4. GitHub: Repository → Settings → Webhooks, Content type „application/json“ (nur erreichbar, wenn der Pi von außen erreichbar ist).

        Dienste

        Welche Kacheln im Widget „Server-Dienste“ angezeigt werden. Änderungen werden sofort gespeichert.

        Wake-on-LAN

        Geräte, die im Dashboard per Klick geweckt werden können. Wake-on-LAN muss im BIOS / in der Netzwerkkarte des Geräts aktiviert sein.

        Web-Dienste

        Eigene Dienste und Geräte im Heimnetz oder VPN, deren Erreichbarkeit der Pi regelmäßig prüft – Webseiten, Text auf einer Seite, JSON-Werte, TCP-Ports, Ping und DNS-Server. Antwortzeiten und Vorfälle zeigt ein Klick auf den Dienst in der Web-Dienste-Karte des Dashboards.

        Prüfung hinzufügen

        Alle Prüfungen nur im Heimnetz oder VPN. „Webseite“: jede Antwort unter HTTP 400 zählt als erreichbar – auch eine Login-Seite. Ohne „Zertifikat prüfen“ werden auch selbst-signierte Zertifikate akzeptiert. Geräte aus dem Netzwerk-Scan lassen sich unter System-Werkzeuge → Geräte im Netzwerk mit einem Klick überwachen (Ping, folgt der IP über die MAC-Adresse).

        Alarmierung

        –

        Kritische Ereignisse werden zum Alarm, der quittiert werden muss – im Dashboard (System → Alarme) oder mit dem Link in der Mail, ohne Anmeldung. Bleibt ein Alarm unquittiert, wird nach der eingestellten Zeit die nächste Stufe benachrichtigt. Versendet wird über die E-Mail-Einstellungen; die normale Ereignis-Mail lässt dann weg, was als Alarm kommt.

        Eskalationskette

        Empfänger: Benutzernamen (mit hinterlegter E-Mail-Adresse) oder E-Mail-Adressen, mehrere mit Komma.

        Wartungsfenster

        Geplante Arbeiten an allen oder einzelnen Diensten. Während eines Wartungsfensters zählen Ausfälle der betroffenen Dienste nicht gegen die Verfügbarkeit, die Statusleiste zeigt nur einen Hinweis und die öffentliche Statusseite „Wartung“. Geplante Fenster der nächsten 14 Tage kündigt die Statusseite an.

        Eigene Links

        Links zu deinen Diensten (Home Assistant, Router, Grafana …). Sie erscheinen oben im Dashboard unter „Links“ und in der Suche (Strg+K) – auf allen Geräten.

        Freigabe-Links

        Aktive Download-Links für einzelne Dateien (erstellt in der Datei-Vorschau). Jeder mit dem Link kann die Datei ohne Anmeldung laden, bis der Link abläuft oder du ihn beendest.

        Austausch-Links

        Ein Link für einen ganzen Ordner – zum Hochladen (z.B. Logs oder Fotos von anderen einsammeln), zum Herunterladen (alle Dateien des Ordners) oder für beides. Ohne Anmeldung, mit Ablaufdatum und Größenlimit; vorhandene Dateien werden nie überschrieben, Unterordner und versteckte Dateien nie gezeigt.

        Auto-Update

        Der Pi prüft jede Minute GitHub und installiert neue Versionen automatisch – je nach Kanal jeden neuen Commit oder nur veröffentlichte Releases (Tags vX.Y.Z). Auf dem stabilen Kanal geht es nie auf ein älteres Release zurück.

        Verlauf

        Messwerte für das Verlaufsdiagramm (CPU, Temperatur, RAM, Netzwerk, Lüfter).

        Datenaufbewahrung

        Wie lange aufgezeichnete Daten bleiben und wie viele Versionen behalten werden. Älteres wird stündlich gelöscht; „Jetzt aufräumen“ macht das sofort und gibt den Platz der Datenbank frei. Diese Werte gelten für den gerade gewählten Pi.

        Speicherbedarf

        Selbstdiagnose

        Prüft die Installation des Dashboards selbst: Dienst und Auto-Update, sudo-Regeln, Rechte der Dateien mit Zugangsdaten, Datenbank, Python-Pakete, Uhrzeit, Docker- und Kubernetes-Zugriff, Remote-Pis und E-Mail. Zu jedem Problem steht, wie es sich beheben lässt. Läuft zusätzlich einmal täglich; Probleme erscheinen in der Statusübersicht. Gilt für den gerade gewählten Pi.
